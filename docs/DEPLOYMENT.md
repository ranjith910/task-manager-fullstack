# Deployment

The setup used for the live demo:

| Part | Where | Notes |
| ---- | ----- | ----- |
| Database | MongoDB Atlas (free M0 cluster) | |
| API | Render (free web service) | `render.yaml` in the repo root |
| Frontend | Vercel | `frontend/vercel.json` |

The frontend calls `/api/...` on its own domain and Vercel forwards those requests to Render. From the browser's point of view the API is same-origin, so the `httpOnly` auth cookie is a normal first-party cookie (`SameSite=Lax`) and there are no CORS or third-party cookie issues (Safari blocks third-party cookies by default).

## 1. MongoDB Atlas

1. Create a free cluster.
2. **Database Access**: add a user with a strong password and the *Read and write to any database* role (or scope it to the `tasknix` database).
3. **Network Access**: allow `0.0.0.0/0`. Render's free plan doesn't have fixed outbound IPs.
4. **Connect > Drivers** and copy the connection string. Add a database name before the `?`:

   ```
   mongodb+srv://<user>:<password>@<cluster>.mongodb.net/tasknix?retryWrites=true&w=majority
   ```

## 2. API on Render

1. Push the repo to GitHub.
2. In Render: **New > Blueprint**, select the repo. Render reads `render.yaml` and creates the `tasknix-api` service.
3. Fill in the two variables it asks for:
   - `MONGO_URI`: the Atlas connection string
   - `CLIENT_URL`: your Vercel URL, e.g. `https://tasknix.vercel.app` (you can come back and set this after step 3)
4. `JWT_SECRET` is generated by Render. `NODE_ENV=production` turns on secure cookies and hides error details.
5. When the deploy finishes, open `https://<your-service>.onrender.com/api/health`. It should return `{"success":true,"database":"connected"}`.

`RESET_DEMO_ON_START=true` creates the demo account (`demo@tasknix.app` / `demo1234`) on the first start, and puts its tasks back every time the service wakes up. Visitors can use it but can't change its profile or password.

> Free Render services sleep after 15 minutes without traffic, so the first request after that takes around 30 to 50 seconds. The frontend shows a "waking up the server" message while it waits.

## 3. Frontend on Vercel

1. If your Render URL is not `https://tasknix-api.onrender.com`, update the `destination` in `frontend/vercel.json` and push.
2. In Vercel: **Add New > Project**, import the repo and set **Root Directory** to `frontend`. Vercel detects Vite automatically.
3. Optional environment variables (to show the "Try the demo account" button):
   - `VITE_DEMO_EMAIL=demo@tasknix.app`
   - `VITE_DEMO_PASSWORD=demo1234`
4. Deploy, then make sure `CLIENT_URL` on Render matches the Vercel URL.

## 4. Check the live site

- Register a new account, log out, log back in
- Create, edit, complete and delete a task
- Refresh the page: you should still be logged in and see the same tasks
- Open the site in a private window: you should be sent to `/login`

### Check `TRUST_PROXY` once

Some rate limits are per IP, so the API has to know which IP is the real visitor. Requests pass through Vercel and then Render's own proxies, each one adds an entry to `X-Forwarded-For`, and `TRUST_PROXY` says how many of those to skip.

1. Look up your public IP (for example on https://ifconfig.me).
2. Use the live site for a moment, then open the service's **Logs** in Render.
3. Each request line starts with the IP the API saw. If it's your IP, you're done.
4. If it's some other address (the same one for every visitor), raise `TRUST_PROXY` by one and redeploy. Otherwise every visitor shares one rate limit bucket.

This check only catches a value that is too low. The API is also reachable directly on its `onrender.com` address, where a caller can send a made up `X-Forwarded-For` and get a fresh per-IP bucket on every request. That's why failed logins are also limited per account and wrong current passwords per user, and those limits don't depend on the IP.

## Environment variables

### Backend

| Name | Required | Description |
| ---- | -------- | ----------- |
| `MONGO_URI` | yes | MongoDB connection string |
| `JWT_SECRET` | yes | Secret used to sign tokens. At least 32 characters in production |
| `NODE_ENV` | | `production` on Render |
| `PORT` | | Render sets this automatically |
| `JWT_EXPIRES_IN` | | Session length, default `7d` |
| `CLIENT_URL` | | Allowed browser origin(s) for CORS, comma-separated |
| `COOKIE_SAME_SITE` | | `lax` (default). Use `none` only if the browser calls the API on another site directly |
| `TRUST_PROXY` | | Number of proxies in front of the API (`4` in `render.yaml`, see the check above) |
| `DEMO_EMAIL`, `DEMO_PASSWORD` | | The shared demo login, default `demo@tasknix.app` / `demo1234` |
| `RESET_DEMO_ON_START` | | `true` to (re)create the demo account and its tasks when the server starts |

### Frontend

| Name | Description |
| ---- | ----------- |
| `VITE_API_URL` | Only if the API isn't reachable at `/api` on the same domain |
| `VITE_DEMO_EMAIL`, `VITE_DEMO_PASSWORD` | Show the demo login button |

Never commit `.env` files. Only the `.env.example` files are tracked.
